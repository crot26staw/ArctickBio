# АрктикБио — вёрстка сайта

## О проекте
Статическая вёрстка сайта **АрктикБио** (бренд АрктикБиоМарин, морской коллаген) на сборщике **Vite**. Готовая вёрстка в дальнейшем натягивается на **WordPress + WooCommerce** (отдельный этап, делается не здесь). Всё, что верстаем, должно легко переноситься в PHP-шаблоны темы.

Общение с пользователем — на русском языке.

## Порядок работы (важно)
1. Страницы верстаются **по одной**, в порядке, который задаёт пользователь (список страниц он даёт по ходу работы).
2. Сначала только **десктоп (1440)**. Планшет и мобилку **не делаем**, пока пользователь не проверит десктоп и явно не даст команду на адаптив.
3. После команды на адаптив — адаптируем под планшет, затем под мобилку.
4. Не переходить к следующей странице без подтверждения пользователя.
5. Если в макете что-то неясно (состояния, ховеры, отсутствующие тексты/картинки, анимации) — спрашивать, а не додумывать.
6. После вёрстки секции — сверять с макетом визуально (скриншот страницы vs `get_screenshot` из Figma).

## Стек
- Vite 8 (multi-page): `root` = `src/`, каждая страница — отдельный `.html` в `src/`, все прописаны в `vite.config.js` → `pages`.
- SCSS (модульный синтаксис `@use`), минификация Lightning CSS (встроена в Vite 8).
- Ванильный JS (ES-модули), без фреймворков. GSAP для анимаций. **Lenis** — плавный скролл (`js/modules/smooth-scroll.js`, CSS `lenis/dist/lenis.css` в секции Vendor `main.scss`). Слайдеры — только после согласования, предпочтительно Swiper (установлен; CSS подключается в `main.scss` в секции Vendor, не из JS — иначе перебивает наши стили).
- Partials — собственный плагин `vite/html-include.js` (см. ниже).

## Partials (vite/html-include.js)
```html
<include src="partials/header.html"></include>
<include src="partials/product-card.html" data='{"title": "Коллаген", "price": "1440₽"}'></include>
```
- Путь `src` — от `src/`. В partial переменные пишутся как `{{ title }}`, незаполненные → пустая строка.
- `data` — JSON в **одинарных** кавычках, поэтому внутри текста не использовать `'`.
- Partials могут подключать другие partials. При изменении partial дев-сервер делает full reload.
- Секции страницы лежат в `partials/<страница>/` (например `partials/home/hero.html`) — это будущие template parts.

## Правила вёрстки
- **БЭМ** для классов (`block__element--modifier`). Никаких стилей по тегам и id (кроме base/reset).
- Семантичная разметка, один `h1` на страницу.
- Цвета — CSS custom properties (`var(--color-accent)` и т.д.) из `_variables.scss`; шрифты, контейнер, брейкпоинты — SCSS-переменные.
- Размеры — `rem(px)` (функция из `_functions.scss`), `px` — для бордеров/мелочей.
- **Резиновый rem (px-to-rem)**: `html { font-size }` в `_global.scss` считается от ширины окна (`fluid-root-size()`, ширины макетов — `$design-widths`). 1rem = 16px на 1440 и пропорционально меньше на узких экранах. Макета под 1920 нет: выше 1440 вёрстка растёт вдвое медленнее окна (`$fluid-growth: 0.5`) и останавливается на 1920 (`$fluid-max-width`, там 1rem ≈ 18.67px, контейнер ≈ 1680px). Масштабируем только целиком — сцены с абсолютными позициями в rem иначе разъедутся. Поэтому всё, что должно масштабироваться, пишем в `rem()`, а не в `px`. На планшете (≤1199) база 768, на мобилке (≤767) — 375.
- Типографика — миксины из `_mixins.scss`, названия как стили в Figma: `h1`, `h2`, `h3`, `body-l`, `display-l`, `display-s`, `body-m`, `body-m-strong`, `body-s`, `body-s-strong`, `desc-l-strong`, `desc-m`, `desc-s`.
- Контейнер `.container`: на всю ширину окна, поля по 50px (`rem(50)`, на 1440 ровно 50) на любой ширине десктопа; max-width — `$container-max-width` (1920px, там же перестаёт расти rem). Не ограничивать контейнеры шириной 1440 — шире макета поля росли (на 1728 было 127px). `$container-width` (1440 в rem) — только для сцен с абсолютными позициями (compound, фон about). Планшет — 20px (`$container-padding-tablet`), мобилка — 10px (`$container-padding-mobile`).
- Мобилка: размеры в `rem()` прямо из макета 375. Стили заголовков мобилки (h2 24px, display-l 32px, display-s 20px) — внутри миксинов типографики, отдельно не переопределять.
- Планшет: размеры в `rem()` берутся прямо из макета 768 (на 768 1rem = 16px). Правки — `@include media(tablet)` внутри того же блока.
- Сцены с абсолютным позиционированием из макета (пачка с саше, состав, процесс) — позиции в rem от «сцены» 1440.
- **desktop-first**: адаптив — `@include media(tablet)` / `@include media(mobile)` (max-width 1199 / 767).
- Ховеры — через миксин `@include hover { ... }` (только для устройств с hover).
- Картинки: `<img>` с `alt`, `width`/`height`, `loading="lazy"` ниже первого экрана. Фото — webp (конвертировать через sharp, ресайзить под размер показа ×2), иконки — svg.
- JS вешается на `data-js-*` атрибуты, не на БЭМ-классы.
- Тексты берём из макета, не lorem ipsum.
- **backdrop-filter дорогой при скролле** (видеокарта размывает фон каждого такого элемента на каждом кадре; замер — ощутимо на 120 Гц):
  не ставить его на непрозрачные плашки и на однотонный фон (там размытие не видно — пример: шапка в светлой теме, `mini-card--solid` в футере);
  для карточек поверх статичной фото-подложки — `fake-glass.js`.
- **Не писать `-webkit-backdrop-filter` вручную**: Lightning CSS склеивает его с `backdrop-filter` и выкидывает непрефиксную версию — размытие пропадает. Префиксы он расставляет сам.

## Анимации
- **GSAP** (`gsap` + ScrollTrigger), импорт через `js/modules/motion.js`. Анимации — отдельными модулями в `js/modules/`, инициализация по `data-js-*`.
- Учитывать `prefers-reduced-motion` (`prefersReducedMotion()` из `motion.js`).
- **Плавный скролл — Lenis** (`smooth-scroll.js`). Крутит GSAP-тикер (`gsap.ticker` → `lenis.raf`, `lagSmoothing(0)`), на каждый кадр скролла вызывается `ScrollTrigger.update`, поэтому ScrollTrigger-анимации работают как обычно, без scrollerProxy. Скролл остаётся нативным (window), `scrollY` и событие `scroll` работают.
  - При `prefers-reduced-motion` Lenis не включается.
  - Программный скролл — `getLenis()?.scrollTo(target)` (не `window.scrollTo`), якорные ссылки `href="#id"` Lenis скроллит сам (`anchors: true`).
  - Модалки/меню: `getLenis()?.stop()` при открытии, `start()` при закрытии.
  - Блок со своим внутренним скроллом (список, попап) — атрибут `data-lenis-prevent`.
  - Не задавать `scroll-behavior: smooth` в CSS — конфликтует с Lenis.
- **Появление about** (комментарии в Figma + скрины пользователя): about доходит до верха экрана и закрепляется (pin всей `.sachet-journey` на `APPEAR.pin` = 2.6 экрана). Сначала стика и карточек нет; по скроллу стик выезжает снизу (160px) и почти сразу становится непрозрачным (`APPEAR.sachetFade` — дизайнер: долгий полупрозрачный подъём выглядит «как привидение»), затем карточки (`data-js-sachet-journey-card`, `initCards`, настройки `CARDS`; комментарий дизайнера, референс asana-spa.ru): на десктопе карточки по очереди целиком поднимаются из прозрачности (пустых плашек быть не должно — просьба пользователя), следом их содержимое (y 44 → 0, иконка `data-js-sachet-journey-card-icon` ещё scale 0.9 → 1), горы `data-js-sachet-journey-bg` scale 1.07 → 1; на планшете/мобилке (стопка) первая карточка на месте, остальные без фейда въезжают снизу из позиции «колонкой» и ложатся на предыдущую, затем их содержимое. У карточек своя шкала на путь пина (start/end числами из pinTrigger) в `gsap.matchMedia` — пин не пересоздаётся. В конце пауза (`APPEAR.length`) — в ней начинает подниматься облачная завеса.
- **Облачная завеса about → product-scene** (референс white-desert.com; `initVeil` в `sachet-journey.js`, настройки — `VEIL`): `.cloud-veil` (в `.sachet-journey`, картинка about-clouds.webp + белая заливка, 3 экрана) поднимается снизу в 2 раза быстрее скролла с конца пина about, закрывает его; когда экран закрыт целиком — about прячется (autoAlpha 0), product-scene выходит из облаков: снизу завеса срезана маской (`--veil-cut-start/end`, пересчёт каждый кадр по верху секции, `VEIL.cut` — доли высоты скалы `[data-js-cloud-veil-edge]`), поэтому ровный край скалы всё время под облаками (комментарий дизайнера); остаток завесы растворяется, пока product-scene подходит к верху экрана (`VEIL.fadeStart/fadeEnd` = 0.75–0.95 экрана после конца пина); с fadeStart стик снова за передней стенкой пачки. y завесы — в координатах обёртки, шкала из двух отрезков (во время пина обёртка стоит, после — едет со скроллом). Летящий стик на время завесы поднимается над ней (z-index 5), после рассеивания возвращается за переднюю стенку пачки. Но пока карточки about видны, стик ЗА ними (z 2, карточки стеклянные — он просвечивает размытым, не обрезать!); над завесой (z 5, целиком) — только когда облака плотно накрыли верх карточек под ним (`VEIL.dense`) или about спрятан. Проверка каждый кадр тикера — `isStickAboveVeil`. Всё по скроллу (scrub), фаза 1 в `sachet-journey.js`; двигает `<img>` стика, а перелёт — его обёртку. Перелёт стартует от конца пина (start/end числами — у закреплённой обёртки ScrollTrigger сдвигает позиции).
- **Переход about → product-scene** (макет: 18126:51425, 18126:51426, 18126:51464): в `index.html` обёртка `.sachet-journey` вокруг двух секций, в ней летящий стик; `sachet-journey.js` (ScrollTrigger, scrub) переносит его в позицию `[data-js-sachet-journey-target]` в пачке с уменьшением. Слои через z-index: карточки about 3 > стик 2 > камни; передняя стенка пачки 3. У `.product-scene__product` и цели нельзя использовать transform (ломает слои и расчёт offset).
- **Переход product-scene → catalog** (только ≥768: на мобилке по комментарию дизайнера catalog не наезжает, `gsap.matchMedia` в `sachet-journey.js`): product-scene — 100svh. После перелёта стика внешняя обёртка `.sachet-journey-cover` закрепляется (pin без pinSpacing) на высоту product-scene, catalog (`z-index: 2`) наезжает сверху (фаза 3, `initCover` в `sachet-journey.js`). Второй pin — именно на внешней обёртке: два пина на `.sachet-journey` ломают первый. У обёртки `display: flow-root`, чтобы margin-top из hero-cover.js не схлопывался наружу. GSAP оставляет на закрепляемой обёртке `transform`, а внутри элемента с transform `position: fixed` не держится, поэтому у пина about стоит `pinReparent: true`: на время закрепления `.sachet-journey` переносится в `body`. Стили `.sachet-journey` и всего, что внутри, не должны зависеть от родителей.
- **Наезд следующей секции на предыдущую (без JS)**: обёртка `.overlap-stack` (`scss/blocks/_overlap-stack.scss`) — первая секция внутри `position: sticky; top: 0`, последняя поверх (`z-index: 1`). Обе секции — 100svh. Сейчас: compound → video. Внутри GSAP-пинов не использовать (там — пин, как у product-scene → catalog).
- **Заголовки и описания** (комментарий дизайнера, референс kononenkogroup.com): атрибут `data-js-title-reveal` → `title-reveal.js` (GSAP SplitText по строкам с маской `mask: 'lines'`: каждая строка выезжает снизу из-под маски, yPercent 130 → 0, 1.1s, stagger 0.1s, ease cubic-bezier(0.17,0.84,0.44,1), без прозрачности и blur; запуск при появлении, один раз). Ставить на все новые заголовки секций и описания под ними (lead, абзацы). Маска выше строки на 0.15em (`.title-line-mask` в `_global.scss`) — иначе при line-height 0.9–1.2 обрезаются хвосты букв. Свой момент запуска — `data-title-reveal-start` (по умолчанию `top 85%`; в about `top 56%` — строки выезжают, когда about, наезжая на hero, прошёл чуть больше половины экрана (верх секции на ~43% высоты); на первом экране ниже 85% высоты — `top bottom`, иначе без скролла не запустится). Тот же эффект (по скроллу, scrub) — у `data-reveal-sequence-split` в reveal-sequence.js. До разбивки заголовок скрыт (класс `js` на `<html>` + `.is-split`).
- **Элементы и карточки** (комментарий дизайнера, референс drinksom.eu): `fade-up.js` — из прозрачности снизу, 32px, 0.8s, ease cubic-bezier(0.16,1,0.3,1), один раз при появлении. `[data-js-fade-up]` — сам элемент, `[data-js-fade-up-group]` — дети по очереди (шаг 0.15s), `data-fade-up-delay`, `data-fade-up-start` (по умолчанию `top 85%`). Сдвиг — CSS-свойством `translate`, не transform (у витаминов свой translateY). Не ставить внутри закреплённых сцен (about, «Процесс», «Исследования», benefits) и на элементы reveal-sequence. Сейчас: hero (слайдер товаров, задержка 0.6), карточка видео, витамины «Состава», compound-stats, «О компании»: фото intro, лента сотрудников, соцсети, слайдер новостей.
